# FRP QuickStart 服务端安装指南

## 系统要求

- **操作系统**: Ubuntu 20.04+ / Debian 11+ / CentOS 8+ 或其他 Linux 发行版
- **架构**: x86_64 (AMD64)
- **内存**: 最低 512MB，推荐 1GB+
- **磁盘**: 100MB 可用空间
- **网络**: 公网 IP 或 NAT 端口转发
- **ACME 模式**: 公网 `80/tcp` 必须可访问，服务器上需要安装 `acme.sh`

## 一、准备并上传服务端

### 方法 1: 从 Windows 本机上传发布包（当前推荐）

在项目根目录执行：

```powershell
# 生成 Linux x64 自包含服务端
powershell -ExecutionPolicy Bypass -File .\release\publish-linux-x64.ps1

# 整理成 release 压缩包
Copy-Item -Force .\artifacts\linux-x64-self-contained\server\frpquick-server .\release\server-linux-x64\frpquick-server
tar -czf .\release\frpquick-server-linux-x64.tar.gz -C .\release\server-linux-x64 frpquick-server

# 上传到 VPS。把 key.pem、用户名和公网 IP 换成自己的。
scp -i "C:\path\to\key.pem" .\release\frpquick-server-linux-x64.tar.gz ubuntu@<你的公网IP>:/home/ubuntu/
```

SSH 登录 VPS 后解压：

```bash
mkdir -p ~/frpquickstart
tar -xzf ~/frpquick-server-linux-x64.tar.gz -C ~/frpquickstart
cd ~/frpquickstart

# 添加执行权限
chmod +x frpquick-server
```

### 方法 2: 从 GitHub Release 下载（可选）

只有当你已经在 GitHub Releases 上传了 `frpquick-server-linux-x64.tar.gz` 后，才能使用这种方式。当前仓库没有一键安装脚本，不要使用不存在的 `scripts/install-server.sh`。

```bash
wget https://github.com/FaQxD233/frpquickstart/releases/download/vX.Y.Z/frpquick-server-linux-x64.tar.gz
mkdir -p ~/frpquickstart
tar -xzf frpquick-server-linux-x64.tar.gz -C ~/frpquickstart
cd ~/frpquickstart
chmod +x frpquick-server
```

## 二、首次启动

### 交互式配置

```bash
cd ~/frpquickstart
./frpquick-server
```

首次运行会引导你完成配置：

1. **自动生成配置文件**: `server-config.json`
2. **API 密钥**: 自动生成，首次显示后不会再明文打印（请妥善保存）
3. **TLS 加密模式**:
   - `none` - 不加密（仅限可信网络）
   - `self-signed` - 自动生成自签证书，客户端需要指纹
   - `acme` - 调用 acme.sh 获取 Let's Encrypt shortlived IP 证书（**推荐**）

### 命令行参数启动

```bash
# 使用自签证书模式
./frpquick-server --tls self-signed

# 使用 Let's Encrypt shortlived IP 证书
# 前提：已安装 acme.sh，公网 IP 可从外网访问 80 端口
./frpquick-server --tls acme --acme-id 203.0.113.10 --acme-email admin@example.com

# 指定配置文件
./frpquick-server --config /path/to/config.json
```

### ACME 模式说明

安装 acme.sh：

```bash
curl https://get.acme.sh | sh -s email=admin@example.com
```

`acme` 模式会在启动时调用 `~/.acme.sh/acme.sh`：

```bash
acme.sh --issue --standalone --server letsencrypt --cert-profile shortlived -d <公网IP> --days 7 --keylength 2048
acme.sh --install-cert -d <公网IP> \
  --cert-file runtime/acme/cert.pem \
  --key-file runtime/acme/key.pem \
  --fullchain-file runtime/acme/fullchain.pem
acme.sh --install-cronjob
```

服务端加载 `runtime/acme/fullchain.pem` 和 `runtime/acme/key.pem`。acme.sh 续期覆盖文件后，新连接会自动重新加载证书，无需手动指定证书路径。

如果服务以普通用户运行，`acme.sh --standalone` 需要能监听 `80/tcp`。Ubuntu 上可给 `socat` 添加低端口绑定能力：

```bash
sudo setcap cap_net_bind_service=+ep "$(readlink -f /usr/bin/socat)"
```

### 客户端分享链接

服务端启动成功后会打印一条 `frpquick://` 分享链接，例如：

```text
frpquick://203.0.113.10:9080/?tls=acme&secret=<API密钥>
```

`self-signed` 模式会额外包含 `fp=<证书指纹>`。如果 `PublicAddress` 为空，服务端会尝试自动查询公网 IPv4 生成链接，适合 AWS/Lightsail 这类服务器内部配置不是公网 IP 的场景。

分享链接包含 API 密钥，请只通过可信渠道发送给客户端用户。客户端粘贴这条链接后，只需要再填写本地端口和要开放的公网端口。

## 三、配置说明

配置文件 `server-config.json` 示例：

```json
{
  "ControlBindAddress": "0.0.0.0",
  "ControlPort": 9080,
  "PublicAddress": "your-server-ip",
  "FrpsBindPort": 7000,
  "ApiSecret": "生成的密钥",
  "FrpAuthToken": "生成的token",
  "AllowedRemotePortStart": 10000,
  "AllowedRemotePortEnd": 60000,
  "RuntimeDirectory": "runtime",
  "TlsMode": "acme",
  "AcmeShPath": "~/.acme.sh/acme.sh",
  "AcmeIdentifier": "",
  "AcmeAccountEmail": "",
  "AcmeRenewDays": 7,
  "AcmeProfile": "shortlived",
  "AcmeKeyLength": "2048"
}
```

**重要配置项**：

- `PublicAddress`: 你的服务器公网 IP（客户端连接需要）
- `ControlPort`: 控制端口，默认 9080
- `FrpsBindPort`: frps 监听端口，默认 7000
- `ApiSecret`: 客户端认证密钥
- `AllowedRemotePortStart/End`: 允许分配的公网端口范围

## 四、防火墙配置

### Ubuntu/Debian (ufw)

```bash
sudo ufw allow 9080/tcp   # 控制端口
sudo ufw allow 7000/tcp   # frps 端口
sudo ufw allow 80/tcp     # ACME HTTP-01 校验
sudo ufw allow 10000:60000/tcp  # 公网端口范围
sudo ufw reload
```

### CentOS/RHEL (firewalld)

```bash
sudo firewall-cmd --zone=public --add-port=9080/tcp --permanent
sudo firewall-cmd --zone=public --add-port=7000/tcp --permanent
sudo firewall-cmd --zone=public --add-port=80/tcp --permanent
sudo firewall-cmd --zone=public --add-port=10000-60000/tcp --permanent
sudo firewall-cmd --reload
```

### 云服务器安全组

如果使用阿里云/腾讯云/AWS 等云服务器，需要在**安全组/防火墙规则**中开放：
- TCP 9080 (控制端口)
- TCP 7000 (frps)
- TCP 10000-60000 (公网端口范围)
- TCP 80 (ACME HTTP-01 校验，仅 `--tls acme` 需要)

## 五、配置为系统服务（推荐）

### 创建 systemd 服务

```bash
sudo tee /etc/systemd/system/frpquickstart.service > /dev/null <<EOF
[Unit]
Description=FRP QuickStart Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=$USER
WorkingDirectory=$HOME/frpquickstart
ExecStart=$HOME/frpquickstart/frpquick-server --tls acme --acme-id <你的公网IP> --acme-email admin@example.com
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
EOF
```

### 启动服务

```bash
# 重载配置
sudo systemctl daemon-reload

# 启动服务
sudo systemctl start frpquickstart

# 设置开机自启
sudo systemctl enable frpquickstart

# 查看状态
sudo systemctl status frpquickstart

# 查看日志
sudo journalctl -u frpquickstart -f
```

### 检查服务状态

```bash

ps aux | grep frpquick-server

# 检查端口监听
ss -tlnp | grep -E '(9080|7000)'

# 测试健康检查（HTTP 模式）
curl http://localhost:9080/health

# 测试健康检查（ACME 模式）
curl https://<你的公网IP>:9080/health

# 测试健康检查（self-signed 模式）
curl -k https://localhost:9080/health
```


## 七、获取连接信息

启动服务后，记录以下信息（客户端需要）：

1. **服务器地址**: `PublicAddress` 或你的公网 IP
2. **API 密钥**: 从配置文件查看：`cat server-config.json | grep ApiSecret`
3. **TLS 模式**: 推荐 `acme`；仅 `self-signed` 模式需要服务启动时打印的证书指纹
4. **分享链接**: 服务启动时打印的 `frpquick://...`，可替代手动填写服务器地址、控制端口、TLS 模式、API 密钥和证书指纹

## 八、常见问题

### 1. 端口被占用

```bash
# 查找占用端口的进程
sudo lsof -i :9080
sudo lsof -i :7000

# 停止占用进程或修改配置文件中的端口
```

如果是客户端指定的公网端口被旧隧道记录占用，例如 `38080`，优先访问管理界面：

```text
https://<你的公网IP>:9080/admin
```

用 `ApiSecret` 登录后可以：

- 点击"清理离线记录"批量删除已经不再占用端口的历史隧道。
- 在离线隧道行点击"释放端口"删除单条记录。
- 对在线隧道点击"强制关闭"。该操作会重启由 `frpquick-server` 托管的 `frps`，所有在线隧道都会断开并等待客户端重连。

服务端在处理新的指定端口申请时，也会先检查旧记录对应端口是否已经实际释放。如果端口已经空闲，会自动释放内存中的旧占用，避免离线老隧道继续造成冲突。

### 2. 证书文件损坏

```bash
# 删除旧证书，重新生成
rm -rf runtime/server-cert.*
sudo systemctl restart frpquickstart
```

### 3. ACME 申请失败

```bash
# 确认 acme.sh 已安装
~/.acme.sh/acme.sh --version

# 确认 80 端口可被公网访问，standalone 校验需要占用 80 端口
sudo lsof -i :80

# 先用 staging 环境测试，避免触发 Let's Encrypt 生产限额
./frpquick-server --tls acme --acme-id <公网IP> --acme-staging

# 检查生成的证书是否是 7 天 shortlived IP 证书
openssl x509 -in runtime/acme/fullchain.pem -noout -issuer -dates -ext subjectAltName
```

### 4. 权限不足

```bash
# 确保程序有执行权限
chmod +x frpquick-server

# 如果使用 1024 以下端口，需要 root 权限
sudo ./frpquick-server
```

### 5. frps 启动失败

```bash
# 查看详细日志
sudo journalctl -u frpquickstart -n 50

# 检查 frps 二进制文件
ls -lh runtime/frp/frps
```

## 九、升级服务

先在 Windows 本机重新发布并上传：

```powershell
powershell -ExecutionPolicy Bypass -File .\release\publish-linux-x64.ps1
Copy-Item -Force .\artifacts\linux-x64-self-contained\server\frpquick-server .\release\server-linux-x64\frpquick-server
tar -czf .\release\frpquick-server-linux-x64.tar.gz -C .\release\server-linux-x64 frpquick-server
scp -i "C:\path\to\key.pem" .\release\frpquick-server-linux-x64.tar.gz ubuntu@<你的公网IP>:/home/ubuntu/
```

然后在 VPS 上替换：

```bash
# 停止服务
sudo systemctl stop frpquickstart

# 备份配置和证书
cp -r runtime runtime.bak
cp server-config.json server-config.json.bak

# 解压新版本
tar -xzf ~/frpquick-server-linux-x64.tar.gz -C ~/frpquickstart
chmod +x frpquick-server

# 恢复配置
cp server-config.json.bak server-config.json
cp -r runtime.bak/* runtime/

# 重启服务
sudo systemctl start frpquickstart
```

## 十、卸载

```bash
# 停止并禁用服务
sudo systemctl stop frpquickstart
sudo systemctl disable frpquickstart

# 删除服务文件
sudo rm /etc/systemd/system/frpquickstart.service
sudo systemctl daemon-reload

# 删除程序文件
rm -rf ~/frpquickstart
```
